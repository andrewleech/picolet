# Picolet v1.2 Implementation Plan — macOS Support

This plan turns [v1.2-spec.md](v1.2-spec.md) into a phased delivery
schedule continuing the scrum loop from v1.1. Phases PH24–PH30 sit on
top of the v1.1 work landed in PH00–PH23.

## Loop shape

Same as v1 and v1.1:

```
scrum-planner ─▶ scrum-developer ─▶ scrum-sqe ─▶ scrum-tester
                       ↑                              │
                       └────── fix loop on FAIL ──────┘
```

After PH30 passes its tester gate, `scrum-po` runs the v1.2 acceptance
audit against [v1.2-spec.md](v1.2-spec.md).

## Conventions

Inherited from [CLAUDE.md](../CLAUDE.md): same `dev` branch, signed
`[PHnn]` commits, per-phase artefact at
`docs/phases/PHASE_NN_<slug>.md`, WSL2 native + dockcross build hosts.

New for v1.2:

- macOS builds run on GitHub Actions `macos-13` (x64) and `macos-14`
  (arm64) runners. There is no local macOS build path from the WSL2
  dev box — every phase that produces a macOS binary requires a CI
  run.
- Phase exit gates for macOS phases must be verified using CI-built
  binaries; the tester downloads and verifies them from the CI
  artifact store.
- Phases that only modify Python, YAML, or build scripts can be
  verified locally; phases that compile C code or produce new Mach-O
  binaries require CI.
- The CLAUDE.md build and test policy footnote "macOS is out of scope
  for v1" is superseded for v1.2 and should be updated in PH29.

## Critical path

```
PH24 ──┬─▶ PH25 ──▶ PH26 ─┐
       │                    ├─▶ PH29 ──▶ PH30
       └─▶ PH27 ──────────┘
PH28 (pydfu) can run in parallel with PH25–PH27 after PH24 is green.
```

- PH24 (cli runtime) is the prerequisite for all subsequent macOS
  phases. It proves the unix port builds on Darwin and validates the
  build pipeline shape before the more complex renderer work begins.
- PH25 (WKWebView binding) is the highest-risk phase and the critical
  path bottleneck. Its exit gate directly enables PH26.
- PH27 (LVGL/SDL2) is independent of PH25 and can run in parallel.
- PH28 (pydfu/libusb) is independent of PH25–PH27 and can overlap
  with any of them after PH24.
- PH29 wires CI once all runtime variants are proven.
- PH30 is the acceptance audit and cannot start until PH29 is green.

## Model tier defaults

Each phase declares recommended model for each role. Defaults (per
CLAUDE.md):

- `opus` — planning, acceptance, complex C, FFI bindings, anything
  cross-cutting.
- `sonnet` — bulk implementation, tests, validation.
- `haiku` — lookups, formatting, trivial scaffolding.

## Phases

### PH24 — macOS cli runtime variants

**Goal**: Build `picolet-runtime-macos-x64-cli` and
`picolet-runtime-macos-arm64-cli` natively on the respective GitHub
Actions runners. Prove the existing unix port overlay + romfs trailer
mechanism works on Darwin / Mach-O without modification or with minimal
changes.

**Deliverables**:
- `build-runtime.sh` gains a `macos-x64` and `macos-arm64` build path
  using native `clang` (no Docker container).
- macOS CI is stubbed in `release.yml` with a single `cli` variant
  to prove the pipeline shape; full matrix expansion happens in PH29.
- Both macOS cli artifacts pass the existing size gate (NFR-MAC-1,
  ≤ 1 MiB).
- Both artifacts execute a frozen `main.py` via the romfs mechanism
  and exit with the correct status.
- `docs/macos-unsigned.md` created with the Gatekeeper workaround.

**Exit gate**: FR-RT-MAC-1 (cli only), FR-RT-MAC-3, FR-RT-MAC-4,
FR-RT-MAC-5, FR-BP-MAC-4, FR-BP-MAC-5, NFR-MAC-1.
**Model tiers**: planner `opus`, developer `sonnet`, sqe `sonnet`,
tester `sonnet`.

### PH25 — WKWebView libffi binding

**Goal**: The `picolet_webview_mac.c` C glue and its Python counterpart
`_mac_ffi.py`. ObjC runtime via `libobjc.dylib` + `objc_msgSend`.
Window creation (NSWindow), WKWebView embed, JS→Python postMessage
bridge, picolet:// URL scheme handler, WKWebView snapshot API.

This is the hardest phase in v1.2. The design mirrors `picolet_webview2.c`
(Win32 COM dispatch) but targets the ObjC message-passing ABI instead.

**Deliverables**:
- `overlay/ports/unix/variants/picolet-webview/picolet_webview_mac.c` —
  the macOS C glue compiled only when `__APPLE__` is defined.
- `packages/picolet-runtime/python/picolet_ui/_mac_ffi.py` — libffi
  bindings into `WebKit.framework`, `AppKit.framework`,
  `Foundation.framework` via `ffi.open`.
- `_app.py` gains a `sys.platform == "darwin"` branch that imports
  `_mac_ffi` instead of `_gtk_ffi`.
- `PICOLET_TEST_MODE=1` path: enable WKWebView remote inspection, pick
  a free port, announce on stderr.

**Exit gate**: FR-WV-MAC-1 through FR-WV-MAC-8 (excluding full CI
integration which is PH29). A macos-x64-webview binary built in CI
passes the hello-webview demo: window opens, IPC round-trips.
**Model tiers**: planner `opus`, developer `opus`, sqe `sonnet`,
tester `opus`.

### PH26 — macOS webview runtime variant

**Goal**: Wire PH25 into the full webview build pipeline. Produce
`picolet-runtime-macos-{x64,arm64}-webview` artifacts that pass the
full webview test suite.

**Deliverables**:
- `mpconfigvariant.mk` for macOS webview variant updated with any
  Darwin-specific linker flags (`-framework WebKit -framework AppKit
  -framework Foundation`).
- All four example apps build and pass their Playwright test suites
  against macOS webview binaries.
- NFR-MAC-2 (≤ 2 MiB) passes.

**Exit gate**: FR-WV-MAC-1 through FR-WV-MAC-8, FR-EX-MAC-1 (webview
examples), NFR-MAC-2.
**Model tiers**: planner `sonnet`, developer `sonnet`, sqe `sonnet`,
tester `sonnet`.

### PH27 — macOS LVGL via SDL2-Cocoa

**Goal**: Build `picolet-runtime-macos-{x64,arm64}-lvgl`. SDL2 has a
native Cocoa backend; this should be near-trivial once PH24 is green.

**Deliverables**:
- macOS lvgl build path in `build-runtime.sh`: `brew install sdl2` is
  the only prerequisite. No from-source SDL2 build needed (unlike
  Windows, where the static MXE build was required).
- `hello-lvgl` template builds and runs on both macOS targets.
- NFR-MAC-3 (≤ 2 MiB) passes.

**Exit gate**: FR-LV-MAC-1 through FR-LV-MAC-3, FR-EX-MAC-1 (hello-lvgl),
NFR-MAC-3.
**Model tiers**: planner `sonnet`, developer `sonnet`, sqe `sonnet`,
tester `sonnet`.

### PH28 — macOS pydfu (libusb dylib)

**Goal**: Make the pydfu example app work on macOS. The only macOS-
specific change is the libusb dylib name and load path.

**Deliverables**:
- `_usb/core.py` gains a `sys.platform == "darwin"` branch:
  `ffi.open("libusb-1.0.dylib")`. dyld resolves via the Homebrew
  prefix without extraction.
- `romfs_extract.py`'s macOS branch is confirmed to return the path
  unchanged (already correct for Linux — macOS is the same code path
  since `sys.platform != "win32"`).
- pydfu's Playwright tests pass on macOS (using the existing mock USB
  shim; real USB hardware not required in CI).
- The runtime SBOM entry for libusb is updated to include
  `targets = ["linux-x64", "windows-x64", "macos-x64", "macos-arm64"]`.

**Exit gate**: FR-EX-MAC-1 (pydfu), FR-EX-MAC-2, FR-EX-MAC-3.
**Model tiers**: planner `sonnet`, developer `sonnet`, sqe `sonnet`,
tester `sonnet`.

### PH29 — macOS CI integration

**Goal**: Full CI build matrix. Add `macos-13` and `macos-14` runners
to `release.yml`. Add macOS lane to `perf-check.yml`. Produce all 6
macOS artifacts per release. Update CLAUDE.md's macOS footnote.

**Deliverables**:
- `release.yml` extended: `target: [linux-x64, windows-x64, macos-x64,
  macos-arm64]` with runner selection based on target name.
- Per-variant Homebrew install step: `brew install sdl2` (lvgl) and
  `brew install libusb` (pydfu — not needed for the runtime itself).
- `perf-check.yml` macOS lane on `macos-14`: measures NFR-MAC-5 and
  the NFR-TEST-1 equivalent. Window-visibility polling via `pgrep`
  + timing (no xdotool on macOS).
- CLAUDE.md updated: macOS footnote in "Build and test policy" section
  changed to "macOS targets are in scope for v1.2; see docs/v1.2-plan.md
  for build instructions."
- FR-CI-MAC-1 through FR-CI-MAC-5 pass on a tag-triggered workflow run.

**Exit gate**: FR-CI-MAC-1 through FR-CI-MAC-5, NFR-MAC-5 (perf lane
green), all 12 macOS artifacts (6 binaries + 6 SBOMs) uploaded to a
test GitHub Release.
**Model tiers**: planner `sonnet`, developer `sonnet`, sqe `sonnet`,
tester `sonnet`.

### PH30 — macOS acceptance audit

**Goal**: `scrum-po` runs the v1.2 spec audit. Every FR-RT-MAC-*,
FR-WV-MAC-*, FR-LV-MAC-*, FR-BP-MAC-*, FR-CI-MAC-*, FR-TEST-MAC-*,
FR-EX-MAC-*, and NFR-MAC-* gets a Yes / No verdict with file:line
evidence and a pointer to the CI run that produced the artifact.

A No on any requirement sends control back to the planner for a
targeted fix-up phase (PH30a, PH30b, etc. as needed).

**Exit gate**: All v1.2 FR and NFR pass the PO audit.
**Model tiers**: planner `opus`, developer varies, sqe `sonnet`,
tester `opus`.

## Acceptance

After PH29 passes its tester gate, `scrum-po` runs the v1.2 spec
audit (PH30): every FR-* and NFR-* in [v1.2-spec.md](v1.2-spec.md)
gets a Yes / No verdict with file:line evidence. A No on any
requirement sends control back to the planner for a fix-up phase.

## Backlog (post-v1.2)

- Code signing and notarisation for distribution (v1.3).
- Universal (fat) Mach-O binaries combining x64 and arm64.
- App bundle (`.app`) and DMG packaging via `picolet bundle`.
- `picolet build --from-source` for macOS (requires resolving osxcross
  SDK licensing).
- ARM Linux targets.
