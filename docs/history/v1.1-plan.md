# Picolet v1.1 Implementation Plan — Examples Epic

This plan turns [v1.1-spec.md](v1.1-spec.md) into a phased delivery
schedule continuing the scrum loop from v1. Phases PH17–PH23 sit on top
of the v1 work landed in PH00–PH16.

## Loop shape

Same as v1:

```
scrum-planner ─▶ scrum-developer ─▶ scrum-sqe ─▶ scrum-tester
                       ↑                              │
                       └────── fix loop on FAIL ──────┘
```

After PH23 passes its tester gate, `scrum-po` runs the v1.1 acceptance
audit against [v1.1-spec.md](v1.1-spec.md).

## Conventions

Inherited from [CLAUDE.md](../CLAUDE.md): same `dev` branch, signed
`[PHnn]` commits, per-phase artefact at
`docs/phases/PHASE_NN_<slug>.md`, WSL2 native + dockcross build hosts.

New for v1.1:

- Each example app lives at `packages/picolet/picolet/templates/<name>/`
  for `picolet init` consumption, and at `examples/<name>/` as a checked-in
  worked source tree for development + screenshot capture. The two are
  the same content; the `examples/<name>/` copy is the authoritative
  source and is mirrored into `picolet.templates/` by a script.
- Test artefacts per example live at `examples/<name>/tests/` and run
  via `picolet test`.
- Screenshot artefacts per example live at `examples/<name>/screenshots/`
  and are regenerated by `picolet test --screenshot`. They are committed
  to the repo; drift fails CI.
- `examples/` was an empty directory at v1 close (review finding C2);
  it becomes populated by PH18.

## Critical path

```
PH17 ──┬─▶ PH18 ─┬─▶ PH19   (pydfu — industrial)
       │        ├─▶ PH20   (notes — editorial)        ─┐
       │        ├─▶ PH21   (config — brutalist)        ├─▶ PH23
       │        └─▶ PH22   (dashboard — data-dense)    ─┘
       └─ (LVGL test API used by future LVGL examples — backlog)
```

PH19–PH22 can run in parallel after PH18 lands the Vue toolchain.

## Phases

### PH17 — Autonomous test + remote-control infrastructure

**Goal**: Make every Picolet runtime variant scriptable from outside the
process so designs can be screenshotted and exercised without human
hands. This phase enables every later phase's exit gate.

**Deliverables**:
- `PICOLET_TEST_MODE=1` env var honoured by all three webview runtime
  variants (Linux WebKitGTK, Windows WebView2).
  - WebKitGTK path: enable Web Inspector + `WEBKIT_INSPECTOR_SERVER`
    on `127.0.0.1:<chosen-port>`.
  - WebView2 path: pass `--remote-debugging-port=<chosen-port>
    --remote-debugging-address=127.0.0.1` to the underlying Chromium
    process via `ICoreWebView2EnvironmentOptions::AdditionalBrowserArguments`.
  - Port chosen by binding `0` first to find a free one; announced on
    stderr as `picolet:test-port=<N>`.
- LVGL test API: `picolet._test` module (frozen when
  `PICOLET_TEST_MODE=1`) exposing `tap(x, y)`, `press(key)`,
  `snapshot() -> bytes` (PNG). Snapshot is wired to
  `lv_snapshot_take(scr, LV_COLOR_FORMAT_RGB888)` + a PNG encoder. The
  test API uses `lv_indev_drv_*` synthetic input devices.
- `picolet.cli.test_cmd` implementing `picolet test`:
  - `picolet test <binary>` — spawn, wait for `picolet:test-port=...`,
    print connection info, exit (for tooling that drives further).
  - `picolet test --screenshot <png> <binary>` — spawn, wait-ready,
    snapshot, terminate.
  - `picolet test --run <script.py> <binary>` — spawn, run the given
    Python test script with `AppHarness` pre-imported.
- `picolet.testing.AppHarness` helper exported from `picolet-cli` (not the
  runtime — this is host-side test infrastructure):
  - `AppHarness(binary, browser="webkit"|"chromium").start()`
  - `harness.page` returns the Playwright Page after waiting for an
    in-page `window.picolet.__ready__ = true` flag.
  - `harness.snapshot(path)` calls into the renderer's screenshot API.
  - `harness.stop()` terminates cleanly.
- xvfb integration for Linux CI: `picolet test` detects an absent display
  and wraps the child in `xvfb-run -a -s "-screen 0 1280x800x24"`.
- Windows: relies on the headed window (WSL interop). Future: WebView2
  headless mode (`--headless`).
- `tests/phase-17/run.sh` exercises `picolet test --screenshot` against
  `hello-webview` and `hello-lvgl`. Asserts PNG > 1 KB and is valid PNG
  via Python `Pillow`. Asserts no `PICOLET_TEST_MODE` in any
  `target/*/release/` binary built without the env var.

**Exit gate**: FR-TEST-{1,2,3,4,5,6}, NFR-TEST-{1,2}.
**Model tiers**: planner `opus`, developer `opus` (CDP + COM glue),
sqe `sonnet`, tester `opus`.

### PH18 — Vue 3 + Vite toolchain integration

**Goal**: Make Vue 3 + Vite + TypeScript a first-class frontend
toolchain inside `picolet build`. Establishes `examples/with-vue/` as the
baseline that PH19–PH22 each consume.

**Deliverables**:
- `examples/with-vue/` baseline: Vue 3 + Vite + TypeScript, single
  page demonstrating `picolet.invoke` and `picolet.on` from a Vue
  Composition-API component.
- `packages/picolet-bridge-js/src/picolet.d.ts` — TypeScript declaration
  for `window.picolet`, exported as part of the package.
- `packages/picolet/picolet/templates/hello-vue/` — template
  consumed by `picolet init <name> --template hello-vue`.
- `picolet.toml [ui.frontend]` table:
  ```toml
  [ui.frontend]
  framework = "vue"
  build_cmd = "npm run build"
  dist_dir = "dist"
  dev_url = "http://localhost:5173/"
  ```
  Defaults: `framework = "vanilla"`, no other keys needed. When
  `framework = "vue"`, `picolet build` runs `npm install` (idempotent),
  then `build_cmd`, then packs `dist_dir/` contents into romfs at the
  configured `[ui] root`.
- `picolet dev` extension: when `[ui.frontend].framework = "vue"`, spawn
  `npm run dev` alongside the watcher; webview points at `dev_url`
  during dev. On exit, terminate Vite cleanly via child-process group.
- A documented Vite config (`examples/with-vue/vite.config.ts`) that:
  - Sets `base: './'` so relative asset URLs work under the `picolet://`
    scheme handler (registered by PH09's Step-12 fix).
  - Includes `vue-tsc` for typechecking.
  - Imports `picolet-bridge-js` types via TS path mapping.
- Update `docs/architecture.md` with an explicit "frontend toolchains"
  section noting Vue as the documented path; vanilla still supported.
- `tests/phase-18/run.sh` builds `examples/with-vue/`, asserts the
  binary launches, asserts `picolet.invoke` round-trips a string via
  AppHarness + Playwright.

**Exit gate**: FR-VUE-{1,2,3,4,5}.
**Model tiers**: planner `opus`, developer `sonnet`, sqe `sonnet`,
tester `sonnet`.

### PH19 — pydfu example app

**Goal**: A real DFU flasher GUI demonstrating Picolet for a low-level
hardware-adjacent app. Aesthetic: **industrial control panel** —
forge-orange accents on near-black matte, status LEDs, monospace
tabular layouts, command-line audit log along the bottom.

**Deliverables**:
- `examples/pydfu/` Vue app with the following routes:
  - `/` — device list (auto-refreshing every 500 ms) + USB-bus pane
  - `/flash` — file selection + DFU descriptor inspection + flash flow
  - `/log` — full event log (filterable)
- Python side (`src/main.py`):
  - `@picolet.command async def list_devices()` — uses host
    `/dev/bus/usb/*` on Linux via the pydfu code (the same code from
    `/home/anl/pydfu-win/micropython/tools/pydfu.py`) frozen into the
    app's `.mpy` set. On Windows, WinUSB via libffi.
  - `@picolet.command async def read_dfu(path)` — host FS, parses the
    `.dfu` file structure.
  - `@picolet.command async def flash(device_id, dfu_path)` — runs flash
    in background asyncio task; pushes `dfu:progress` events at each
    block.
  - Host FS access (read `.dfu` files from anywhere) — the framework
    permits it; we use `os.open`/`pathlib` from frozen code.
- Vue side aesthetic:
  - Berkeley Mono display, IBM Plex Sans body (loaded as woff2 from
    romfs — no CDN, NFR-EX-4)
  - `--forge: #ff6b1a`; `--chassis: #0a0c0e`; `--led-ok: #4ade80`;
    `--led-warn: #facc15`; `--led-alarm: #ef4444`; `--rule: #1f2226`
  - Layout: 3-row split — header rail (16px brushed-aluminium gradient
    + serial number), main pane (asymmetric — device list 40% / detail
    60% with a vertical rule), audit log strip (terminal-green
    monospace, 120px tall, autoscrolls)
  - LED dot components: pure-CSS `radial-gradient` with a 1px outset
    `box-shadow` "ring" to imply a recessed mounting; subtle 2 Hz pulse
    when active via `animation: pulse 0.5s ease-in-out infinite`
  - Background: 1×1 px noise texture (data URI base64 PNG, ~400 B)
    overlaid at 4% opacity on the chassis colour — gives a brushed
    finish without paying for an external asset
  - No rounded corners. Hard 1px rules separate panes. Section titles
    are `text-transform: uppercase; letter-spacing: 0.18em; font-size:
    11px`.
  - Buttons: tactile-feeling — outer 1px white-10% shadow + inner
    1px black-40% shadow + 1px solid border + active-state push-in via
    `translateY(1px)` and shadow inversion
- `examples/pydfu/screenshots/` with PNGs for: device-list-empty,
  device-list-populated, flash-start, flash-mid-progress,
  flash-complete, flash-error.
- `examples/pydfu/tests/` with Playwright tests driving the flash
  flow against a mock USB shim (`@picolet.command` overrides in
  `tests/conftest.py`).

**Exit gate**: FR-EX-{1,5,6,7}, NFR-EX-{1,2,3,4,5,6}, NFR-EX-AESTHETIC.
**Model tiers**: planner `opus`, developer `opus`, sqe `sonnet`,
tester `opus`.

### PH20 — notes example app

**Goal**: A focused markdown notes app demonstrating Picolet for a
content-first creative tool. Aesthetic: **editorial / refined** — warm
off-white paper, serif headings, generous margins, single sharp red
accent.

**Deliverables**:
- `examples/notes/` Vue app with routes:
  - `/` — note list (sorted by mtime), with inline search
  - `/edit/:slug` — markdown editor (textarea + live preview)
  - `/about` — minimal about/help screen
- Python side:
  - Storage: `~/.config/notes/` on Linux, `%APPDATA%\notes\` on
    Windows. One `.md` file per note; filename is
    `<slug>-<unix-ts>.md`. Front matter (`title:`, `created:`,
    `updated:`) at the top of each file.
  - `@picolet.command async def list_notes()` — scans the dir, parses
    front matter, returns sorted list.
  - `@picolet.command async def load_note(slug)`,
    `save_note(slug, body)`, `create_note(title)`,
    `delete_note(slug)`.
  - Markdown rendering happens on the JS side (using `marked` bundled
    into Vite output; ~30 KB gzipped, within NFR-EX-3) so the Python
    side stays storage-only.
- Vue aesthetic:
  - GT Sectra display (woff2 in romfs), Söhne or Tiempos Text body
    (one of the open-source alternatives if licensing forbids; first
    candidate: **Source Serif 4** for headings, **Source Sans 3** for
    body — both SIL-OFL, ship-safe)
  - `--paper: #f7f3ed`; `--ink: #1a1715`; `--ink-soft: #5b524c`;
    `--mark: #c4392b`; `--rule: #e3dccf`
  - Layout: two-column on `>1000px` (list left at 320px, editor right),
    single-column with a drawer on narrow. Editor pane has 64px
    horizontal padding + 96px top padding to feel like a page. Body
    text is 18px / 1.6 line-height.
  - Heading hierarchy uses italic serif h1 at 42px tracking -1%.
  - Unsaved state: a 2×2 red dot at the top-left of the editor pane,
    not a save button — the unsaved state is the only place red
    appears.
  - Background: a faint vertical paper-grain (CSS repeating linear
    gradient at 0.5% opacity), giving the page a printed-medium feel
    without obvious decoration.
- `screenshots/`: list-empty, list-populated, edit-pristine,
  edit-unsaved, edit-typing-mid, search-active.
- `tests/`: Playwright test creates a note, edits, saves, reopens,
  deletes — asserts host FS state after each step.

**Exit gate**: FR-EX-{2,5,6}, NFR-EX-{1,2,3,4,5,6}, NFR-EX-AESTHETIC.
**Model tiers**: planner `opus`, developer `sonnet`, sqe `sonnet`,
tester `sonnet`.

### PH21 — config-editor example app

**Goal**: A schema-driven config editor demonstrating Picolet for a
technical / utilitarian tool. Aesthetic: **brutalist terminal** —
phosphor green on near-black, monospace everywhere, deliberate ASCII
feel including box-drawing characters in section headers.

**Deliverables**:
- `examples/config-editor/` Vue app with routes:
  - `/` — file picker (host FS browser) + schema picker
  - `/edit` — form for the loaded config
  - `/diff` — pre-save diff confirmation
- Python side:
  - Supports TOML, YAML, JSON. Detection by file extension.
  - `@picolet.command async def load(path)` — reads + parses, returns
    `{ format, document, schema_hint? }`.
  - `@picolet.command async def validate(format, document, schema)` —
    runs `jsonschema`-style validation. Schemas live in
    `~/.config/config-editor/schemas/`.
  - `@picolet.command async def save(path, format, document)` —
    serialises and writes; returns the unified-diff vs. on-disk so the
    JS side can render the diff view.
- Vue aesthetic:
  - Atyp Mono display (or **JetBrains Mono** as ship-safe fallback —
    OFL) at varying sizes; same family for body
  - `--bg: #0d1b0d`; `--fg: #a3ff7c`; `--fg-dim: #4a8a4a`;
    `--error: #ff5cd1`; `--cursor: #a3ff7c`
  - Layout: full-bleed terminal feel. 80-column max width centred on
    wide screens (deliberately retro). Section dividers use
    `═════════════` rules.
  - Field labels are inline ASCII: `key = ▌ value █`. Cursor block
    blinks via CSS keyframes when input focused.
  - Validation errors show as inline magenta with a leading `!! `
    prefix and a magenta underline; passing fields stay green.
  - Diff view uses literal `+` / `-` line prefixes and unified-diff
    formatting; no syntax highlighting (deliberate — the brutalist
    point is unmediated text).
  - Background: nothing. Solid `#0d1b0d`. The visual interest is the
    text itself.
- `screenshots/`: file-picker, edit-toml, edit-yaml-with-errors,
  diff-add, diff-delete.
- `tests/`: Playwright test loads a TOML schema-conformant file,
  modifies a value, runs validation (passes), saves, asserts
  on-disk content matches.

**Exit gate**: FR-EX-{3,5,6}, NFR-EX-{1,2,3,4,5,6}, NFR-EX-AESTHETIC.
**Model tiers**: planner `opus`, developer `sonnet`, sqe `sonnet`,
tester `sonnet`.

### PH22 — dashboard example app

**Goal**: A live system-metrics dashboard demonstrating Picolet for a
data-dense observability use case. Aesthetic: **sophisticated
data-dense** — slate base, ice-blue chart strokes, amber warning
accents, condensed display type, dense layered information.

**Deliverables**:
- `examples/dashboard/` Vue app with a single page (route `/`) showing:
  - Top strip: hostname / uptime / load-avg (large numerals)
  - Grid of widgets:
    - CPU line chart (last 60s, 1 Hz samples)
    - Memory gauge (radial)
    - Per-core sparkline strip
    - Network throughput dual-line (rx / tx)
    - Disk I/O dual-line (read / write)
    - Process count + top-5 list (refreshes 1 Hz)
- Python side:
  - Background asyncio task at 1 Hz reads `/proc/stat`,
    `/proc/meminfo`, `/proc/net/dev`, `/proc/diskstats`, `/proc/loadavg`
    on Linux; uses `psutil`-equivalent ffi calls or
    `GetSystemTimes`/`GlobalMemoryStatusEx` on Windows.
  - Pushes a single `metrics:tick` event per second with the full
    payload (one event > many — smaller IPC overhead).
  - History buffer (60 samples) stored Python-side; on first connect,
    the JS side requests `get_history()` to bootstrap the charts.
- Vue aesthetic:
  - GT America Condensed display (or **Antonio** as ship-safe
    fallback — OFL), Roobert Mono numerals (or **JetBrains Mono**),
    GT Walsheim body (or **DM Sans** — OFL)
  - `--bg-0: #0b0e12`; `--bg-1: #101418`; `--bg-2: #161b22`;
    `--ink: #e5e7eb`; `--ink-soft: #94a3b8`; `--chart: #7dd3fc`;
    `--chart-2: #c4b5fd`; `--accent: #f59e0b`; `--alarm: #ef4444`
  - Layout: 12-column grid, widgets span varying columns. Asymmetric
    arrangement — the CPU chart is 8 cols × 2 rows, the gauge is 4 cols
    × 2 rows, sparkline strip is 12 × 1, etc. Information density
    matches Bloomberg terminal logic — every pixel earns its place.
  - Numerals are massive (60px) with `font-variant-numeric:
    tabular-nums`. Units are 11px, uppercase, dim.
  - Chart implementation: hand-rolled SVG paths driven by Vue refs;
    chart.js too heavy and visually generic. Path `d` attribute updates
    every tick. Smooth 200ms transition via `path { transition: d
    200ms cubic-bezier(0.4, 0, 0.2, 1); }`.
  - Background: gradient mesh — 3 large radial-gradients at ~5%
    opacity in the chart-blue + accent-amber palette, layered. Gives
    atmospheric depth without competing with the data.
  - Each widget has a 1px `--bg-2` border + `box-shadow: 0 1px 0 0
    rgba(255,255,255,0.04)` highlight at the top — implies a slight
    bezel.
- `screenshots/`: full-dashboard, full-dashboard-with-warning,
  cpu-pinned-state, network-active-state.
- `tests/`: Playwright test waits for two consecutive `metrics:tick`
  events, asserts widget DOM updated between them.

**Exit gate**: FR-EX-{4,5,6}, NFR-EX-{1,2,3,4,5,6}, NFR-EX-AESTHETIC.
**Model tiers**: planner `opus`, developer `opus` (Vue + SVG dataviz),
sqe `sonnet`, tester `sonnet`.

### PH23 — Examples meta + integration

**Goal**: Mirror `examples/<name>/` content into the templates package
so `picolet init` works, write the cross-example README, regenerate the
top-level screenshots gallery, and confirm CI runs the screenshot
gallery as part of release.

**Deliverables**:
- `scripts/mirror-examples-to-templates.sh` — copies
  `examples/<name>/{src,ui,picolet.toml}` into
  `packages/picolet/picolet/templates/<name>/`. Runs in CI; a
  drift between `examples/` and `picolet.templates/` is a CI failure.
- Updated `packages/picolet/picolet/init_cmd.py` to advertise the
  four real templates in `--help` output and to handle the Vue-app
  template-name templating (replaces `<<APP_NAME>>` in
  `package.json` `name` field + `picolet.toml [app] name`).
- `examples/README.md` — overview of the four apps with thumbnails
  pointing at each example's `screenshots/` directory.
- `.github/workflows/release.yml` — adds a "regenerate screenshots"
  job that runs `picolet test --screenshot` against each example under
  xvfb; commits the resulting PNGs to a `screenshots-vX.Y.Z` branch as
  a PR for human review. (Auto-merge is not enabled — visual changes
  should be deliberate.)
- `docs/examples.md` — narrative tour of the four apps emphasising what
  each demonstrates about the framework:
  - pydfu: host FS + USB + long-running tasks + progress events
  - notes: host FS persistence + multi-route Vue + markdown rendering
  - config-editor: structured-data manipulation + validation pipeline
  - dashboard: 1 Hz event push + history buffer + custom dataviz
- Update `README.md` at the repo root: link to `examples/` and embed
  a 2×2 thumbnail grid of the four apps.

**Exit gate**: all four templates discoverable via `picolet init
--list-templates`; all four `screenshots/` directories non-empty and
present on `main`; CI screenshot job green.
**Model tiers**: planner `sonnet`, developer `sonnet`, sqe `sonnet`,
tester `sonnet`.
