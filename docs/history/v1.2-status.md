# Picolet v1.2 build status

## PH24 — macOS cli runtime variants

PH24 lays down all source-side configuration for `macos-x64` and
`macos-arm64` cli runtime artifacts. No macOS binary is produced
during this commit pass — that requires a CI run on GitHub-hosted
macOS runners.

### What is in place after PH24

- `packages/picolet/picolet/_targets.py` — `TARGET_MACOS_X64`,
  `TARGET_MACOS_ARM64` constants; `host_target()` returns the correct
  constant on Darwin; `SUPPORTED_TARGETS` includes both.

- `packages/picolet-runtime/scripts/build-runtime.sh` — `build_macos()`
  function that runs natively on Darwin (no Docker). Guards:
  - `--from-source` for `macos-*` exits with an actionable error.
  - Running on a non-Darwin host exits with an actionable error.
  - `MACOSX_DEPLOYMENT_TARGET=11.0` (NFR-MAC-9).
  - Darwin-aware `strip -x` (not `--strip-unneeded`).
  - Size gate for `NFR-MAC-1` (1 MiB cli ceiling).
  - SBOM sidecar emission (FR-BP-MAC-6).

- `.github/workflows/release.yml` — `build-macos` job matrix running
  `macos-13` (x64) and `macos-14` (arm64), triggered on release tags
  only (NFR-MAC-10). First step captures `sw_vers`, `uname -m`, and
  `which clang` and uploads `macos-runner-info-<runner>.txt` (FR-CI-MAC-6).

- `packages/picolet-runtime/sbom/runtime.toml` — macOS-specific libusb
  dylib entry; `macos-x64` and `macos-arm64` added to the supported
  targets comment.

- `docs/macos-unsigned.md` — Gatekeeper workaround documentation
  (NFR-MAC-6).

- `tests/phase-24/run.sh` — parses downloaded `macos-runner-info-*.txt`
  artifacts and asserts macOS >= 11.0 (NFR-MAC-9). Skips gracefully when
  artifacts are absent.

### How to verify PH24

1. Push the `dev` branch and trigger the release workflow manually:

   ```
   gh workflow run release.yml --ref dev
   ```

   Or push a `runtime-v*` tag to trigger automatically.

2. Wait for the `build-macos / build macos-x64 / cli` and
   `build-macos / build macos-arm64 / cli` jobs to complete.

3. Check the job logs for the "Build macOS cli runtime" step. A
   successful run ends with `=== Build complete: ... ===` and a size
   line showing the binary is under 1 MiB.

4. Download the `runtime-macos-x64-cli` and `runtime-macos-arm64-cli`
   artifacts from the Actions run summary page.

5. Download the `macos-runner-info-macos-13` and
   `macos-runner-info-macos-14` artifacts and run the PH24 test:

   ```
   bash tests/phase-24/run.sh --artifact-dir <download-dir>
   ```

6. On a macOS arm64 machine, test the binary directly:

   ```
   xattr -d com.apple.quarantine picolet-runtime-macos-arm64-cli
   ./picolet-runtime-macos-arm64-cli --help
   wc -c picolet-runtime-macos-arm64-cli   # must be <= 1048576
   ```

## PH25 — WKWebView binding

PH25 adds the Python wrapper layer and supporting infrastructure for the
macOS WKWebView backend.  The C glue (`picolet_webview_mac.c` / `.h`) was
committed in the prior session at `4ff5d71`.

### What is in place after PH25

- `packages/picolet-runtime/python/picolet_ui/_mac_ffi.py` — libffi bindings
  for all 18 exported `picolet_wkwv_*` symbols.  Mirror of `_win_ffi.py`
  using `ffi.open(None)` → `dlopen(NULL)` on Darwin.

- `packages/picolet-runtime/python/picolet_ui/_webview.py` — macOS `Webview`
  class added as an `elif sys.platform == "darwin":` branch.  Handles
  scheme handler registration, message handler registration, WKWebView
  creation, bridge JS injection, and `PICOLET_TEST_MODE` inspector wiring.

- `packages/picolet-runtime/python/picolet_ui/_window.py` — macOS `Window`
  class added as an `if sys.platform == "darwin":` branch (NSWindow via
  C overlay, `picolet_wkwv_create_window`).

- `packages/picolet-runtime/python/picolet_ui/_loop.py` — `_mac_pump` async
  coroutine added; drains the C overlay's inbound ring and calls
  `picolet_wkwv_pump_messages` per tick.  `_default_webview_pump` and
  `_run_with_pump` updated to select `_mac_pump` on Darwin.

- `packages/picolet-runtime/python/picolet_ui/_app.py` — `Application.__init__`
  gains an `elif sys.platform == "darwin":` branch that wires the macOS
  Webview with `PICOLET_DEV_URL` support and `picolet://` base URI.

- `packages/picolet-runtime/overlay/ports/unix/variants/picolet-webview/mpconfigvariant.mk`
  — adds `picolet_webview_mac.c` to `SRC_C`, `-fvisibility=hidden` to
  `CFLAGS_EXTRA`, `-Wl,-export_dynamic` + `-framework Cocoa -framework WebKit
  -framework Foundation -framework CoreFoundation` to `LDFLAGS_EXTRA` when
  `uname -s == Darwin`.

- `packages/picolet-runtime/scripts/build-runtime.sh` — `macos-x64/webview`
  and `macos-arm64/webview` case branches marked active (were "not yet
  implemented").

- `packages/picolet-runtime/sbom/runtime.toml` — three Apple system framework
  entries added: `WebKit.framework`, `Cocoa / AppKit`, and `Foundation`.

- `tests/phase-25/test_mac_ffi_imports.py` — import-time smoke test;
  skips on non-Darwin.

- `tests/phase-25/test_objc_signatures.py` — static analysis test;
  verifies `objc_msgSend` cast arities vs call argument counts.  Runs
  on any host including Linux CI.

- `tests/phase-25/run.sh` — shell runner; executes static analysis tests
  on any host; on macOS with a display also builds and launches the binary
  with `PICOLET_TEST_MODE=1` and asserts screenshot > 1 KB.

- `docs/architecture.md` — macOS WKWebView backend section added.

### How to verify PH25

1. Static analysis (any host):

   ```
   python3 -m pytest tests/phase-25/test_objc_signatures.py -v
   ```

2. Runtime smoke test (macOS only):

   ```
   bash tests/phase-25/run.sh
   ```

   Or with a pre-built binary:

   ```
   bash tests/phase-25/run.sh --binary ./picolet-runtime-macos-arm64-webview
   ```

3. Full CI build — trigger `release.yml` workflow with `macos-x64/webview`
   and `macos-arm64/webview` in the build matrix once PH25 is merged to
   `dev`.
